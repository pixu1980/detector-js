API Reference

All classes are plain ES6 classes with getters for detections. Two base classes provide the serialization:

FlagsClass

  • get ua → the UA string in use
  • get root / process / navigator / document → the relevant environment roots (kept available after construction)
  • toFlags() → flattened object of every truthy getter + own data properties
  • toValues() → compact object: booleans collapse into the class "name" key ({ name: 'Chrome' }), other values kept

CssFlagsClass

  • get flags, get cssFlagsPrefix
  • toCssFlags() → ['<prefix>--<flag>--<value>'] strings (used only when cssFlags is enabled)

Asserts

  • Asserts.checkAssert(assert, safe?) — runs a value or function (try/catch when safe)
  • Asserts.all(list, safe?) — every element truthy
  • Asserts.one(list, safe?) — at least one element truthy

@detector-js/software

  • Browser — getters for 60+ browsers (Chrome, Firefox, Safari, Edge, Opera, Brave, Vivaldi, Samsung Internet, DuckDuckGo, Facebook, Instagram, TikTok, Kiwi, HuaweiBrowser, Line, Electron, …) + mobile variants (ChromeMobile, SafariMobile, …); name/version after toValues().
  • Engine — Blink, Gecko, WebKit, Trident, EdgeHTML, Presto, KHTML, Goanna, …
  • OS — Windows, macOS (+ version names Tempo→Sequoia), iOS, Android (+ Cupcake→Pie), Linux (+ distro names), Unix, ChromiumOS, plus legacy/mobile/TV OSs; versionName from toValues().

@detector-js/hardware

  • Platform — desktop, smartphone, tablet, tv, console, bot, mobile
  • CPU — platform, cores, architecture, vendor (intel/amd/arm/apple…), vendor flags. navigator.platform/UA strings are legacy-compat on macOS ("MacIntel" + "Mac OS X 10_15_7" appear on both Intel and Apple Silicon), so the real architecture comes from CPU.upgrade() (Client Hints architecture/bitness) and/or the GPU evidence (WebGL renderer "Apple M1…" → arm64 · vendor 'apple'), refined synchronously by Detector — Detector.upgrade() re-runs it. arm64 is no longer misreported as x64.
  • GPU — webGLVendor, webGLRenderer, vendor, model, renderer (WebGL-based, safe-mode)
  • Device — placeholder base for vendor-specific device flags

@detector-js/feature

MDN Web API catalog: beyond the curated flags below, Feature probes every interface listed in the MDN /docs/Web/API index (currently 1021) via global presence ('X' in window), as camelCase flags (e.g. abortController, rtcPeerConnection, webTransport). The catalog is generated by scripts/update-webapis.mjs into packages/feature/lib/webAPIs.js and exposed to UIs via Detector.PROBES / Feature.APIS ({ globals: [...] }, MDN URL = https://developer.mozilla.org/en-US/docs/Web/API/<Global>, flag = Global.toCamelCase()). Curated flags below always win over the catalog (never shadowed). Constructor-computed flags (instance properties): addEventListener, asyncScript, battery, bluetooth, broadcastChannel, caches, clipboard, cors, credentials, deferScript, fetch, file, fileSystem, fullscreen, fullscreenKeyboard, gamepad, geolocation, historyAPI, indexedDB, intersectionObserver, littleEndian, localStorage, matchMedia, mediaCapabilities, mediaRecorder, mediaSession, nfc, notifications, offscreenCanvas, online, paymentRequest, permissions, querySelector, querySelectorAll, resizeObserver, serial, serviceWorker, speechSynthesis, storage, structuredClone, typedArray, usb, userMedia, vibration, visualViewport, wakeLock, webAssembly, webAuthn, webCrypto, webLocks, webRTC, webShare, webSocket, webXr, worker.

Read-only getters: pointerEnabled, pixelRatio, pointerLock, quirksMode, css3D, cssTransform, cssTransition, deviceMotion, deviceOrientation, contextMenu, classList, placeholder, viewportUnit, remUnit, canvas, svg, webp, webGL, webGL2, webGPU, webVR, touch, forceTouch, pointerEvents, srcset, sizes, pictureElement, dialogElement, deviceMemory (value), touchPoints (value).

AudioFeature — supported, context, formats.{mp3,webm,ogg,opus,wav,m4a}. VideoFeature — supported, formats.{mp4,ogv,webm}.

Methods: toFlags(), toValues(), setCssFlags(), upgrade() (async). Getters: ua, root, process, navigator, document, booleanFlagsValuePropertyName.

await detector.upgrade() — real OS version via Client Hints

Modern macOS browsers keep the legacy-compat UA "Mac OS X 10_15_7" (→ Catalina) even on macOS Sonoma, Sequoia or Tahoe. The real version lives in the high-entropy navigator.userAgentData.getHighEntropyValues(['platformVersion']) (User-Agent Client Hints). upgrade() (auto-started in the constructor, safe/no-op when hints are absent or denied by Permissions-Policy) refreshes detector.os with the real version and name — e.g. { name: 'macOS', version: '26.6.2', versionName: 'Tahoe' }.

Safari (and WebKit): no Client Hints exist, and the UA keeps the legacy-compat "Mac OS X 10_15_7". Since Safari 26 is bundled 1:1 with macOS 26 (Apple renumbered in 2025), the UA Version/26.x token reveals the real version synchronously (no async needed) → Tahoe. Older Safari majors were back-ported across multiple macOS releases, so pre-26 values stay UA-based.

macOS version names (Tempo → Tahoe): 10.0–10.15, 11 Big Sur, 12 Monterey, 13 Ventura, 14 Sonoma, 15 Sequoia — then 26 Tahoe (versions 16–25 do not exist; Apple jumped 15 → 26). Windows names incl. 11 (via hints), Android dessert names Cupcake → Pie then numerical (10–17+).
