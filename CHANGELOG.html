Version 3.0.0 (2025-8-25)

Toolchain (esbuild)

  • esbuild replaces rollup + babel + plugins (see ADR docs/adr/001)
  • builds: per-package CJS/ESM (workspace deps external), root CJS/ESM, self-contained browser bundles
  • fixed global export: dist/detector.browser(.min).js now assigns the Detector class to the global — new Detector() works with a plain <script> tag (previously window.Detector was a namespace object)
  • __VERSION__ injected at build time via esbuild define
  • build targets es2016 + bundled conditional polyfills → old-platform friendly; runtime-agnostic roots (self/window/globalThis/global with typeof guards — Node-safe), fixed bare-window usages (Brave, MSStream) that crashed under Node
  • fix: Chromium-based Edge mis-detected as Chrome — UA token is Edg/ (regex now (?:edge|edg))
  • fix: desktop Opera mis-detected as OperaMobile (OPR token now requires a mobile marker)
  • real OS version via User-Agent Client Hints: modern macOS always sends the legacy-compat UA "Mac OS X 10_15_7" (→ Catalina) even on Sonoma/Sequoia/Tahoe; OS.upgrade() / detector.upgrade() resolve the high-entropy platformVersion and report the real version and name (e.g. 26.6.2 · Tahoe, Windows 11) — auto-started in the constructor, safe no-op when hints are unavailable (Safari/Firefox) or denied (Permissions-Policy ch-ua-high-entropy-values)
  • macOS version names extended to Tahoe (26) — versions 16–25 do not exist (Apple jumped 15 → 26 in 2025); Darwin→marketing mapping (20→11 … 26→26)
  • Safari/WebKit fallback: no Client Hints there, and the UA keeps the legacy "Mac OS X 10_15_7"; since Safari 26 is 1:1 with macOS 26, the Version/26.x token now reveals the real version synchronously (e.g. 26.5 · Tahoe); pre-26 Safari stays UA-based
  • Android current majors (10–17) parse correctly (numerical naming since Android 10)
  • CPU architecture fixed for Apple Silicon: navigator.platform "MacIntel" is a legacy compat string shown on ARM Macs too — it no longer forces x64/intel; the arm64 UA token is no longer mapped to x64 (upstream bug). Real architecture from Client Hints (architecture/bitness, via CPU.upgrade()/detector.upgrade()) or from GPU evidence (WebGL "Apple M1…" → arm64 · apple), refined synchronously at construction — MacBook Pro M1 now reports { architecture: 'arm64', vendor: 'apple' } instead of x64/intel

Monorepo & release readiness

  • npm-workspaces monorepo mirroring v2 layout (@detector-js/{core,feature,software,hardware,detector}, 3.0.0 each)
  • exports map (import/require/types), types (.d.ts), sideEffects, engines, publishConfig, unpkg/jsdelivr
  • zero external runtime dependencies; workspace:* internally (resolved at publish)
